# GameZone — منصة ألعاب عربية مجانية

هذه النسخة تنقل المشروع من صفحة HTML تجريبية إلى تطبيق ويب يعمل بخادم فعلي. تتضمن ألعاب متصفح، حسابات خادمية، لوحة متصدرين مشتركة، دردشة مباشرة، غرف خاصة، ومطابقة تلقائية للعبة إكس أو.

## البنية التقنية

- **الواجهة:** HTML/CSS/JavaScript بدون إطار عمل ثقيل؛ RTL ومتجاوبة للهاتف والكمبيوتر.
- **الخادم:** Node.js + Express (واجهات REST).
- **المصادقة:** bcryptjs لتجزئة كلمات المرور + JWT لجلسة المستخدم.
- **قاعدة البيانات:** SQLite عبر better-sqlite3؛ الحسابات والنتائج محفوظة على الخادم.
- **اللعب الجماعي:** WebSocket (`ws`) للدردشة، الحضور، غرف إكس أو، وتبادل الحركات في الوقت الحقيقي.
- **التكلفة:** لا إعلانات ولا مشتريات. SQLite مناسب لبداية صغيرة؛ يمكن نقل قاعدة البيانات لاحقاً إلى PostgreSQL عند التوسع.

## التشغيل المحلي

يتطلب Node.js 20 أو أحدث.

1. فك ضغط المشروع.
2. انسخ `.env.example` إلى `.env`، وضع قيمة طويلة وعشوائية لـ `JWT_SECRET`.
3. افتح Terminal داخل مجلد المشروع وشغّل:
   ```bash
   npm install
   npm start
   ```
4. افتح `http://localhost:3000`.
5. لتجربة اللعب الجماعي، افتح الموقع في متصفحين/جهازين، أنشئ حساباً في كل منهما، ثم أنشئ غرفة وشارك الرمز أو اضغط «ابحث عن لاعب».

## ما يعمل في هذه النسخة

- إنشاء حساب وتسجيل دخول من خلال الخادم.
- كلمات المرور لا تحفظ كنص صريح؛ تُجزّأ باستخدام bcrypt.
- جلسات JWT لمدة 7 أيام.
- لوحة متصدرين مشتركة محفوظة في SQLite.
- خمس ألعاب فردية: الثعبان، الذاكرة، اختبار السرعة، تخمين الرقم، وركلات الترجيح.
- لعبة إكس أو متعددة اللاعبين عبر WebSocket، غرف برمز، مطابقة تلقائية، جولات جديدة، وإشعارات الحركات.
- دردشة عامة مباشرة للاعبين المتصلين.
- واجهة عربية RTL متجاوبة.

## حدود أمنية مهمة قبل الإطلاق العام

هذه نقطة انطلاق قابلة للتشغيل وليست بعدُ منصة إنتاج كبيرة:
- نقاط الألعاب الفردية تُرسل من المتصفح؛ يستطيع مستخدم متقدم تزويرها. الألعاب التنافسية تحتاج إلى تحقق خادمي من قواعد اللعبة، وحدود معدل الطلبات، ورصد الغش.
- يلزم إضافة حماية brute-force/rate limiting، واستعادة كلمة المرور، والتحقق من البريد/الهاتف، وسياسة خصوصية وشروط استخدام، وأدوات حظر وإبلاغ وإشراف على الدردشة.
- أضف HTTPS/WSS عند النشر، واضبط `JWT_SECRET` قوياً، واستخدم قاعدة بيانات مُدارة/نسخاً احتياطية عند التوسع.
- ذاكرة الغرف والدردشة في هذه النسخة داخل ذاكرة عملية الخادم؛ تنتهي الغرف عند إعادة تشغيله. التوسع لأكثر من خادم يتطلب Redis أو طبقة تنسيق مماثلة.
- لا يوجد نظام أصدقاء أو محادثات خاصة أو ألعاب ثلاثية الأبعاد بعد؛ هذه مراحل لاحقة.

## خطة التنفيذ المقترحة

### المرحلة 1 — الأساس القابل للتشغيل (موجودة في الملفات)
- واجهة عربية متجاوبة.
- مصادقة خادمية وقاعدة بيانات.
- ألعاب فردية ولوحة متصدرين مشتركة.
- WebSocket، غرف خاصة، مطابقة، ودردشة عامة.

### المرحلة 2 — الأمان والموثوقية
- Rate limiting وتحقق أقوى من مدخلات API.
- نتائج موثوقة خادمياً للألعاب التنافسية.
- اختبارات آلية لـ API وغرف اللعب، ومراقبة الأخطاء.
- أدوات بلاغ/حظر ومكافحة إساءة الاستخدام.

### المرحلة 3 — تجربة المنصة
- ملفات اللاعبين، الصورة الرمزية، الإنجازات، التحديات اليومية.
- دعوات الأصدقاء وقائمة الأصدقاء والغرف الخاصة.
- إضافة ألعاب جماعية أخرى (مثل Connect Four أو سباق بسيط).

### المرحلة 4 — الإطلاق المجاني والتوسع
- نشر على خدمة تدعم Node.js وWebSocket، وربط نطاق وHTTPS.
- نقل SQLite إلى PostgreSQL عند الحاجة، واستخدام Redis للغرف/الحضور عند تعدد نسخ الخادم.
- مراقبة الأداء والنسخ الاحتياطي واختبار الهاتف والكمبيوتر.

## ملاحظات نشر
لا يمكن تشغيل اللعب الجماعي الحقيقي من ملف `index.html` وحده؛ يجب تشغيل الخادم ونشره على عنوان عام يدعم WebSocket. لا توجد رسوم أو مزايا مدفوعة مضافة في المشروع.
